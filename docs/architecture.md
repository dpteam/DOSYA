# Архитектура

Как устроена игра изнутри. Если вы пришли чинить баг — читайте сверху вниз,
слои идут от железа к геймплею.

## Слои

```
main.c      цикл 60 Гц, ввод, переключение состояний
  |
game.c      физика, враги, камера, HUD, экраны
  |
render.c    спрайты, тайлы, шрифт, градиенты -> один 8-битный буфер
  |
video.c     Mode 13h, PIT, IRQ1, палитра
  |
железо      VGA A000:0000, PIC, PIT, PC speaker
```

Зависимости идут только вниз. `render.c` не знает про врагов, `video.c` не
знает про тайлы, `game.c` не трогает порты напрямую.

## video.c — платформа

Внутри файла живут **два бэкенда**, выбор по `-DDOSYA_HOST`.

### DOS

* `vid_init()` — одно прерывание BIOS `AX=0013h`, дальше всё напрямую.
  Указатель на кадровый буфер получается через `__djgpp_nearptr_enable()`,
  поэтому запись идёт по плоскому 32-битному адресу, без сегментов.
* `timer_init()` / `kbd_init()` — **не** `__interrupt` функции. Это ловушка:
  обычный `__interrupt` даёт protected-mode адрес, а прерывание приходит в
  real mode. Нужен `_go32_dpmi_allocate_iret_wrapper()` вокруг обработчика,
  иначе первое же прерывание уводит процессор в случайную память.
* `vid_present()` — один `memcpy` 64000 байт в `A000:0000`.

### Host

Тот же интерфейс, но кадр пишется в `build/frames/fNNNN.ppm`, а ввод читается
из текстового скрипта (`DOSYA_SCRIPT`). Это позволяет гонять игру без DOSBox:
быстрее в сотни раз, и работает в CI.

## render.c — рендер

Никакого blitter-состояния. Всё пишет в `g_backbuf` (320×200 байт).

* **Спрайты** — 8-битные, индекс 0 прозрачный, обводка уже вшита в данные при
  генерации.
* **Тайлы** — `r_tile()` для переднего плана, `r_tile_dim()` для фона.
  Второй использует предвычисленную затемнённую копию (`g_tiles_dim`): каждый
  пиксель сдвинут вниз по своей рампе на 4 шага. Так фон читается как «дальше»
  без второго набора арта.
* **Шрифт** — 8×16, CP866, 4096 байт.

### Ловушка с градиентами

Палитра собрана из **рампов** (см. `tools/pal.py`): 30 именованных групп,
в каждой 7–16 оттенков одного цвета.

Наивный градиент «интерполировать между индексом A и индексом B» даёт радугу:
индекс 120 → 40 проходит через все рампы между ними. Поэтому
`r_gradient_v()` принимает **рамп + номер шага**, а не два цвета:

```c
r_gradient_v(0, PLAY_H - 1, PAL_SKY_BASE, PAL_SKY_N, PAL_SKY_N - 1, 3);
```

Я наступил на это один раз, и финальный экран был радужным. Больше не надо.

## game.c — игра

### Fixed point

Позиции и скорости — 8.8: `256` = один пиксель, `x >> 8` — пиксельная
координата. Никаких float: на 486 они были бы медленными, а детерминизм
важнее точности.

| константа | значение | смысл |
|---|---|---|
| `GRAV` | 118 | ускорение падения, px/кадр² |
| `GRAV_HOLD` | 92 | пока кнопка прыжка зажата и она летит вверх |
| `JUMP_V` | −1700 | начальная скорость прыжка |
| `RUN_MAX` | 700 | максимальная скорость бега |
| `MAX_FALL` | 1150 | терминальная скорость |

Прыжок с зажатой кнопкой выше, чем с отпущенной — это и есть «переменная
высота», без отдельного счётчика.

### Коллизии

Три запроса к карте, все — перебор тайлов в AABB:

* `box_hard()` — только твёрдые тайлы. Используется при движении по X и при
  движении вверх (чтобы не пройти сквозь потолок).
* `box_down()` — твёрдые **плюс** односторонние платформы, но платформа
  считается полом только если низ персонажа в прошлом кадре был выше её
  верха. Так на платформу можно запрыгнуть снизу и нельзя провалиться.
* `box_tile_flag()` — «есть ли в этом боксе вода/шипы». Для смертей.

Движение по каждой оси идёт по пикселю за шаг (`move_x`, `move_y`), поэтому
на больших скоростях ничего не проскакивает сквозь стены.

### Состояния

```
TITLE -> INTRO -> PLAY <-> DEAD -> GAMEOVER
                   |
                   +-> LEVEL_DONE -> PLAY (следующий уровень)
                   +-> WIN
```

`ST_DEAD` через 150 кадров сам возвращает в игру или в `GAMEOVER`, чтобы
игрок не жал клавишу, чтобы ему сообщили, что он умер.

### Причины смерти

`DIE_WATER`, `DIE_FALL`, `DIE_SPIKE`, `DIE_ENEMY`. Для каждой — свой список
текста, поэтому «Дося утонула» не появится после удара трактором.

### Автопилот

`autopilot_input()` смотрит на тайл впереди и решает, прыгать или нет. Он не
для игрока: это smoke-тест. `tools/smoke.py` запускает его и проверяет, что
все три уровня проходятся. Если кто-то сломает физику — CI покраснеет.

## main.c — цикл

```c
now = timer_ticks();
acc += now - last; last = now;
if (acc > 120) acc = 120;          // стоп не превращается в телепорт
while (acc >= 16) { acc -= 16; tick(); }
render(); present();
```

Фиксированный шаг 16 мс: 486 и современная машина играют одинаково.
Обрезка на 120 мс — потому что после загрузки уровня накопитель иначе
выдаёт 40 кадров подряд, и Дося успевает умереть, пока экран ещё чёрный.

## sound.c — PC speaker

PIT канал 2 в режиме 3 (square wave), гейт через порт `0x61`. Каждый эффект —
массив `{частота, длительность}`, проигрывается по одному тику за кадр из
`snd_tick()`.

Никакого Sound Blaster: во-первых, его надо детектить, во-вторых, это уже не
та игра.
