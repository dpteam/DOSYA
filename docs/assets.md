# Ресурсы

В репозитории **нет ни одного бинарного ассета**. Всё, что видно на экране,
генерируется из Python-скриптов в `build/gen/`. Это не принципиальность ради
принципиальности: так спрайт можно поправить в диффе, а не в редакторе.

## Пайплайн

```
tools/pal.py        палитра из рампов  ──┐
tools/pix.py        Canvas, обводка    ──┤
tools/art_all.py    спрайты (ASCII)    ──┼──> build/gen/assets.c + assets.h
tools/gen_tiles.py  тайлы (процедурно) ──┤
tools/genfont.py    шрифт (Unifont)    ──┘

tools/genpal.py     палитра ──> build/gen/pal.h
tools/genstrings.py текст   ──> build/gen/strings.h
tools/genlevels.py  уровни  ──> build/gen/levels.c + levels.h
```

Всё вызывается из `tools/build.py` перед компиляцией. Порядок важен: `pal.py`
должен отработать до тех, кто на него ссылается.

## Палитра

`tools/pal.py` описывает палитру как набор **рампов** — групп оттенков одного
цвета:

```python
RAMPS = {
    "green": ([(16, 44, 18), (44, 108, 40), (126, 186, 70)], 12),
    ...
}
```

Второе число — сколько оттенков взять между крайними точками. В итоге
получается 209 записей, и в C на них можно ссылаться по имени:

```c
r_pixel(x, y, PAL_GREEN7);
```

Зачем: искать «тот зелёный» по индексу 47 невозможно, а `PAL_GREEN7` — можно.
Плюс появляется возможность затемнять: `pal.dim_index()` сдвигает индекс вниз
по его же рампе, что и даёт фоновый слой.

## Спрайты

Спрайт описывается ASCII-сеткой и легендой символов:

```python
HEAD = [
    "....hhhhhhhh....",
    "...hhHhhhhhHh...",
    "...hHffffffHh...",
    "...hhfeffefhh...",
]
LEGEND = {"h": "red7", "H": "red5", "f": "skin8", "e": "void0"}
```

`pix.art()` превращает это в индексированный `Canvas`, `pix.outline()`
добавляет обводку в 1 пиксель (она нужна: без неё спрайт сливается с фоном
на любом сложном тайле), `art_all.py` выгружает в C.

Спрайты получают 1 пиксель прозрачного поля по краям, иначе обводка
обрезается по границе.

Всего 33 спрайта: 10 кадров Доси, 5 врагов по 2 кадра, 4 предмета, 4 «морды»
для HUD и фон.

## Тайлы

Тайлы 16×16 рисуются **процедурно**, а не в ASCII: у них должна быть
текстура, а вручную расставлять 256 пикселей шума — бессмысленная работа.

```python
def t_wood():
    """Log wall of an izba: horizontal logs with a dark seam."""
    for y in range(H):
        for x in range(W):
            n = h32(x, y, 21)          # детерминированный шум
            v = 0.40 + (n / 255.0) * 0.16
            if y % 8 == 7: v = 0.14    # шов между брёвнами
            c.set(x, y, ramp("wood", 10, v))
```

`h32()` — хеш от координат. Важно, что он **детерминированный**: при
повторной генерации получится тот же байт в байте результат, и CI это
проверяет.

17 тайлов: земля, трава, кирпич, бревно, забор, вода, грабли, сено, крыша,
камень, платформа, торец бревна, штукатурка, окно, дверь.

## Шрифт

`tools/genfont.py` берёт GNU Unifont (`.hex.gz`) и вытаскивает из него
глифы для **всех 256 символов CP866**. Результат — 4096 байт, ровно то, что
было бы в `vga866.fon` на настоящей DOS-машине.

### Почему CP866, а не UTF-8

DOS не знает про UTF-8. Русская строка в игре — это байты CP866:

```c
#define S_TITLE_1 "\204\216\221\237"   /* ДОСЯ */
```

Записано escape-последовательностями, чтобы компилятор не мог ничего
перекодировать. GCC с `-finput-charset` тут бесполезен: у DJGPP нет iconv, и
он падает с `no iconv implementation`. Проверено.

`tools/genstrings.py` делает это автоматически: текст пишется по-русски в
Python, на выходе — CP866-литералы.

## Уровни

`tools/genlevels.py` собирает уровни из ASCII-сетки и **проверяет их на
честность** перед выгрузкой. Подробности — в [levels.md](levels.md).

## Иконка и баннер

`tools/gen_icon.py` рисует `docs/icon.png` и `docs/banner.png` **из тех же
спрайтов и того же шрифта**, что и игра. Если Дося изменится — иконка
изменится вместе с ней.

Градиенты на иконке дизерятся матрицей Байера 4×4: 12 шагов рампы без
дизеринга читаются как 12 полос, с дизерингом — как градиент.
